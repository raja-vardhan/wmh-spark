# Feature Specification: Scalable Classification Engine

**Feature Branch**: `004-scalable-classification-engine`
**Created**: 2026-04-26
**Status**: Draft
**Input**: User description: "Train and deploy a distributed machine learning ensemble model for initial WMH lesion segmentation."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Train Random Forest from Distributed Feature Matrix (Priority: P1)

A model engineer provides the Feature 3 voxel feature DataFrame with a binary `label` column. The classifier trains a Spark MLlib Random Forest model over the distributed table.

**Why this priority**: The legacy k-NN classifier must be replaced by a distributed ensemble that trains in parallel on Spark workers.

**Independent Test**: Build a synthetic Feature 3 DataFrame with labels and assert training returns a Spark MLlib `RandomForestClassificationModel` inside a pipeline.

**Acceptance Scenarios**:

1. **Given** a labeled Feature 3 DataFrame, **When** the classifier trains, **Then** it fits a Spark MLlib Random Forest model.
2. **Given** a feature DataFrame without `label`, **When** training is requested, **Then** training fails fast with a descriptive validation error.

---

### User Story 2 - Use Feature 3 Columns as ML Features (Priority: P1)

The classifier consumes the tabular voxel feature matrix generated by Feature 3 and assembles the numeric columns into a Spark ML feature vector.

**Why this priority**: The model must operate on the distributed voxel table without returning to MATLAB-style voxel loops.

**Independent Test**: Prepare a training DataFrame and assert the assembled `features` vector contains `t1`, `flair`, `t1_flair_ratio`, and `spatial_prior`.

**Acceptance Scenarios**:

1. **Given** a Feature 3 DataFrame, **When** model training starts, **Then** the configured feature columns are assembled into a Spark vector.
2. **Given** a missing feature column, **When** model training starts, **Then** the classifier raises a `ValueError` listing the missing column.

---

### User Story 3 - Produce Raw Binary Voxel Mask Predictions (Priority: P1)

After training, the model transforms a Feature 3 DataFrame and appends a raw binary lesion prediction column for every voxel.

**Why this priority**: Downstream 3D post-processing expects a binary per-voxel mask before connected component filtering.

**Independent Test**: Train on synthetic features, predict over the same distributed table, and assert `predicted_mask` contains only integers `0` and `1` with row count preserved.

**Acceptance Scenarios**:

1. **Given** a trained model and Feature 3 DataFrame, **When** prediction runs, **Then** every input voxel row receives a `predicted_mask` value.
2. **Given** prediction output, **When** downstream code reads `predicted_mask`, **Then** the values are integer `0` or `1`.

---

### User Story 4 - Parallel Training Partition Plan (Priority: P2)

The classifier prepares the training DataFrame with a configurable number of partitions, defaulting to the four-worker CHPC target.

**Why this priority**: Spark MLlib parallelizes tree construction across partitions and workers; training should not collapse to a single partition.

**Independent Test**: Set `training_partitions=4` and assert the prepared training DataFrame has four partitions and Spark SQL shuffle partitions match.

**Acceptance Scenarios**:

1. **Given** no explicit partition count, **When** classifier configuration is created, **Then** it defaults to four training partitions.
2. **Given** a configured training partition count, **When** training data is prepared, **Then** the DataFrame is repartitioned accordingly and Spark shuffle partitions are aligned.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The classifier MUST use `pyspark.ml.classification.RandomForestClassifier`.
- **FR-002**: The classifier MUST ingest Feature 3 DataFrames containing `t1`, `flair`, `t1_flair_ratio`, `spatial_prior`, and `label`.
- **FR-003**: The classifier MUST assemble numeric feature columns with Spark MLlib transformers.
- **FR-004**: The classifier MUST train with Spark MLlib distributed execution rather than local scikit-learn or k-NN code.
- **FR-005**: The classifier MUST support a default four-partition training plan for the four-worker CHPC target.
- **FR-006**: The classifier MUST append an integer `predicted_mask` column with values `0` or `1` for every voxel during prediction.
- **FR-007**: The classifier MUST preserve input row count during prediction.

### Key Entities

- **ClassificationConfig**: Reproducible Random Forest hyperparameters, feature column names, label column name, prediction column name, and training partition count.
- **Random Forest Pipeline Model**: A Spark MLlib `PipelineModel` containing feature assembly and `RandomForestClassificationModel`.
- **Predicted Voxel Mask**: The raw binary classifier output stored in `predicted_mask` before 3D post-processing.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Training returns a Spark MLlib Random Forest classifier model, not k-NN or local Python model code.
- **SC-002**: Prepared training data uses the configured training partition count.
- **SC-003**: Prediction preserves the number of voxel rows exactly.
- **SC-004**: `predicted_mask` contains only `0` and `1` values.
- **SC-005**: Missing labels or missing Feature 3 columns fail fast with descriptive errors.

## Assumptions

- Feature 3 has already produced a validated, distributed voxel feature DataFrame.
- Labels come from the optional expert mask ingestion path and are stored in a binary `label` column.
- Random Forest hyperparameters are intentionally small for local tests; CHPC runs can override them through `ClassificationConfig`.
