Product Requirements Document (PRD): Distributed UBO Detector Migration

1. System Context & Overview

The objective is to re-engineer the legacy, single-threaded MATLAB UBO Detector algorithm into a scalable, cloud-native Apache Spark pipeline for quantifying White Matter Hyperintensities (WMH).

The system will replace the legacy k-Nearest Neighbors (k-NN) classifier with a parallelized Random Forest model to drastically reduce computational overhead. It transitions data processing from a sequential 3D voxel-looping architecture to a distributed, flattened PySpark DataFrame architecture, effectively democratizing access to large-scale neuroimaging analytics.

2. Infrastructure & Environment Constraints

Environment: Simulated cloud environment via the University of Utah CHPC.

Cluster Configuration: 1 Driver Node (32GB RAM) and 4 Worker Nodes (16GB RAM each).

Tech Stack: Python 3.9, PySpark 3.5, Docker, Spark MLlib.

Data Source: Kaggle WMH Segmentation Dataset (Paired T1, FLAIR, Expert Masks).

3. Core Software Features

Feature 1: Distributed Data Ingestion & I/O Layer

Objective: Securely load and parse heterogeneous 3D MRI sequences into the distributed Spark ecosystem.
Acceptance Criteria:

The system must programmatically ingest paired T1-weighted and FLAIR MRI sequences (NIfTI format).

The system must ingest expert-annotated binary lesion masks to serve as the ground truth for downstream evaluation.

The pipeline must establish secure connections to the storage volume and mount the data efficiently for distributed reading across worker nodes.
Technical Constraint: Memory limits require strict partitioning strategies to prevent Driver Node bottlenecks during initial I/O operations.

Feature 2: Containerized Pre-Processing (HD-BET)

Objective: Standardize skull-stripping to isolate brain tissue prior to PySpark feature extraction.
Acceptance Criteria:

The module must execute the High-Density Brain Extraction Tool (HD-BET) on all incoming raw T1 and FLAIR scans.

The execution must be strictly containerized using Docker to ensure environment stability and consistent skull-stripping across all runs.

The output must successfully strip non-brain tissue (skull, eyes, background) to drastically reduce the total voxel count and prevent confounding variables from reaching the classifier.

Feature 3: Distributed Feature Extraction Engine

Objective: Translate sequential MATLAB feature generation into a vectorized, distributed PySpark architecture.
Acceptance Criteria:

The engine must flatten the 3D MRI arrays into a 2D tabular PySpark DataFrame, where each row represents a single $(X, Y, Z)$ voxel.

The engine must extract and store the raw T1 Intensity and FLAIR Intensity values.

The engine must use vectorized operations to calculate the T1/FLAIR Ratio for every voxel simultaneously.

The engine must map the voxel's coordinates to a standard template to append the Spatial Prior (anatomical probability score) to the DataFrame.
Technical Constraint: DataFrame partitioning must be heavily optimized to prevent Out-of-Memory (OOM) errors during the shuffle phase, given the strict 16GB RAM limit per worker node.

Feature 4: Scalable Classification Engine (Random Forest)

Objective: Train and deploy a distributed machine learning ensemble model for initial WMH lesion segmentation.
Acceptance Criteria:

The legacy k-NN classifier must be entirely replaced with a distributed Random Forest model sourced from the Spark MLlib library.

The model must ingest the distributed tabular feature matrix generated by Feature 3.

The model must utilize parallel training capabilities across the 4 worker nodes.

The output must be a raw binary mask (DataFrame column) predicting 1 (potential lesion) or 0 (healthy tissue) for every voxel.

Feature 5: 3D Post-Processing & Connected Component Labeling

Objective: Filter the raw classification output using volumetric spatial logic to eliminate scanner noise and false positives.
Acceptance Criteria:

The system must reconstruct the flattened, 1D PySpark DataFrame predictions back into a localized 3D matrix.

The algorithm must perform 3D Connected Component Labeling to group adjacent 1s (voxels touching via faces, edges, or corners) into distinct clusters.

The module must calculate the WMH Cluster Size (total voxel count) for each distinct grouping.

The module must enforce a minimum volume threshold, automatically converting clusters that fall below the size threshold back to 0 (healthy/noise).

Feature 6: Automated Evaluation & Benchmarking Suite

Objective: Validate the distributed pipeline's accuracy, scalability, and computational efficiency against the legacy MATLAB baseline.
Acceptance Criteria:

The evaluation module must programmatically calculate the Dice Similarity Coefficient (DSC) between the Spark-generated, post-processed masks and the expert "Silver Standard" masks.

The test suite must assert that the final reproduction accuracy achieves a $DSC > 0.85$.

The suite must benchmark end-to-end processing time per subject to prove reduced latency compared to serial MATLAB execution.

The suite must track and log cluster throughput (subjects processed per hour) as the system scales from 1 to 4 worker nodes to confirm near-linear scalability.
